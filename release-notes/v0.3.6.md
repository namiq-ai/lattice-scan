# lattice-scan 0.3.6

**An AI agent in its own sandbox can now run the host scan and `recent`, and a run with no terminal no longer leaves the list of installed packages in the home folder.** This release changes where and how the tool writes its records. What it looks up, what it compares and what leaves the machine are exactly as in 0.3.5.

## Highlights

- **No crash without a writable home.** With a read-only or missing home folder, the host scan and `recent` used to end in a Python traceback (exit 1) the first time they wrote a record. Now the run says on one line that the folder cannot be written and keeps that run's records in a temporary folder, deleted when the run ends. If `LATTICE_SCAN_DIR` names the folder and it cannot be used, the run stops with exit 1 and one line naming `LATTICE_SCAN_DIR`: a folder you chose is never silently replaced.
- **A run with no terminal leaves nothing behind.** An agent or a cron job with no terminal on standard input or error, and no records folder yet, now writes its records to a temporary folder instead of `~/.lattice-scan`. `--keep` (or `LATTICE_SCAN_KEEP=1`) keeps them in the default folder.
- **Private files.** Every file in the records folder is now created mode 0600 (it was 0664), and files from earlier runs are tightened on the next run.
- **The skill tells a sandboxed agent what to set.** Section 2 of the Claude skill now says to set `LATTICE_SCAN_DIR` to a folder the agent owns, and `LATTICE_API_KEY` if the user gave a key.

## What changes for you

- A folder that already exists (`~/.lattice-scan`, or the older `~/.host-scan`) and any folder named by `LATTICE_SCAN_DIR` are used exactly as before. Nothing changes for a person at a terminal.
- **If you run the host scan from cron or another job with no terminal and relied on the default folder being created**, your findings are no longer remembered from one run to the next. Set `LATTICE_SCAN_DIR` to a folder you keep, or add `--keep`.
- `get-key` never uses a temporary folder, because the key must outlive the run.
- `recent`, `enrich` and `project` write no host records, as before.

## Known limits

- A run whose records went to a temporary folder cannot show an earlier run's findings as `RECORDED` or `OPEN`; every finding in it is new. That is the point for a sandboxed agent, and a cost for a scheduled job that wants history.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read. `recent` lists what was recently added and matches by product name; an empty or all-`unmatch` result is not the same as safe.
- The host check is tested on Debian-family hosts.
- The package is not listed in OpenAI's directory; submitting it is a separate step that needs OpenAI's review.
