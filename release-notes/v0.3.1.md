# lattice-scan 0.3.1

**`recent` reads the current list again, and gains the open list.** If `lattice-scan recent` stopped with "the recent-CVE list has schema 'lattice-recent/3'; this lattice-scan reads lattice-recent/2", this release is the one to install. Nothing else changes: what leaves the machine, the table, the other commands and the exit codes are as in 0.3.0.

## Highlights

- **`recent` reads the list again.** namiq.io's list moved from version 2 to version 3, and 0.3.0 accepted only version 2. The tool now reads version 2 and later versions that only add fields. It checks that the period it needs is in the list, so a list that grows does not stop every installed tool. Version 1, or something that is not the list, is still refused, with a request to upgrade.
- **`recent --open`.** The new open list holds exploited CVEs CISA added before the weekly window but within the last 30 days, overdue first. CISA's due date has passed for most of them, which says nothing about any machine. They are checked against the host in the same way as the daily and weekly lists: only the ones that may match are looked up on Lattice. `--period open` is the same. Weekly is still the default.

## Known limits

- `recent` lists what was recently added, and matches by product name. An empty or all-`unmatch` result is not the same as safe. For a CVE you know of, use `--cve`.
- The open list needs the list's version 3; on an older list `recent --open` says there is no open list.
- The host check is tested on Debian-family hosts.
