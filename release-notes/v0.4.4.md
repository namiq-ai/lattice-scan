# lattice-scan 0.4.4

**A brand-new CVE that Lattice does not hold yet is now explained instead of ignored, and the package page on PyPI describes everything the tool does.** What is sent to Lattice (CVE ids and a key if set) is unchanged.

## Highlights

- **A CVE the graph holds only as a bare node.** A new CVE can be in Lattice as a stub with no NVD record. `lattice-scan --cve ID` used to print only "not in the graph's CISA list" and nothing else, which looked like a failed scan. It now says that the graph has no NVD record, description, EPSS, SSVC, weakness, ATT&CK link or reference for the id yet, that a bare node says nothing about risk, and what to do. When namiq.io's list of recent CVEs has the id (that request carries no id), it adds the product, CVSS and publication date from the list and whether something installed may match the product.
- **The PyPI page is up to date.** The README, which is the package page, now has an overview table of what each command reads and what leaves the machine, and a Use section grouped by purpose that includes `--deep`, `--refresh --inventory`, `--list` and `posture`.
- The skill explains how to report a bare node: no description or score to quote, and not a statement that the CVE is harmless.

## What changes for you

- Nothing breaks. A named CVE that Lattice holds only as a stub shows a short explanation and, when the namiq.io list has it, a line with the product, score and date. It costs no extra Lattice call.

## Known limits

- The line from namiq.io's list exists only for CVEs that list covers (recent exploited and critical ones). For another bare node the tool points to the NVD record and the vendor advisory.
- `posture` is a first look: as a normal user it cannot see other users' processes or the firewall rules, and a process that hides from the user it runs as is out of its reach. Windows and macOS are not covered.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
