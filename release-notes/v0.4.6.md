# lattice-scan 0.4.6

**`lattice-scan recent` now scans everything in namiq.io's recent list, and its summary says what became of every id.** What is sent to Lattice (CVE ids and a key if set) is unchanged: ids that match nothing installed are ruled out on your machine and never sent.

## Highlights

- **`recent` reads the whole list.** It used to read only the weekly part (7 days). The list also has an `open` part: exploited entries CISA added earlier in the last 30 days, overdue first. That part was read only with `recent --open`, and the output never said so. On one day the list held 65 ids and a plain `recent` looked at 33. The default is now `--period all`: weekly and open together, each id once. `--daily`, `--weekly` and `--open` still narrow it, and `--all` names the default. `--max-read` defaults to 200, so the whole list is considered.
- **The summary accounts for every id.** For example: `exploited 32 ruled out, 3 may match; critical 30 ruled out, 0 may match`. A critical id that matches nothing installed is not listed in the table, which used to look like ids missing from "3 exploited and 30 critical read". The summary also says when `--max-read` cut the list.

## What changes for you

- `lattice-scan recent` reads more ids than before (the open part) and prints more `unmatch` rows. Only ids that may match this host are sent to Lattice, so the number of reads changes only if more of the older ids match.
- Running `lattice-scan` with no argument still reads only the daily list. A keyless run that has to look many entries up reaches Lattice's limit of about 20 reads an hour.
- A list without the `open` part (schema 2) still works: `all` is then the weekly part.

## Known limits

- A match is by product name against what is installed. The tool lists candidates for a person to read; it does not decide whether a host is affected, and it does not detect incidents.
- A critical entry that may match is shown as `WATCH`; it is not known to be exploited, so Lattice is not asked about it.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
