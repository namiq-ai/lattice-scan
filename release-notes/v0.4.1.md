# lattice-scan 0.4.1

**A scan now shows detail for every CVE it lists except the ones that matched nothing on this host.** Until now two groups had a table row and nothing else: a CVE you named that CISA does not list, and an open finding from an earlier run. What is matched, how versions are compared and what leaves the machine are as in 0.4.0.

## Highlights

- **A CVE you name that CISA does not list shows what Lattice holds on it.** Under the table: NVD's record status and dates, EPSS and SSVC when present, the weakness, the start of the description, the linked ATT&CK techniques ("likely" when the graph inferred the link) and up to three references. When NVD lists no affected products yet, it says so and that no version check was possible. The heading says that "not listed" is not the same as safe or unexploited. There is no priority line, and nothing is recorded as a finding.
- **An open finding from an earlier run prints its saved detail.** Installed software, dates, CISA's required action, the version check, and the priority, EPSS, SSVC, weakness, description, techniques and references where they were recorded. The block is marked as the detail saved at the time of the earlier run. It is read from the records file: no call, nothing leaves the machine.
- The main table (`RESULT BY CVE`) is unchanged.

## What changes for you

- An unlisted CVE you name costs **one more call**, counted against the keyless limit. It applies only to ids you typed, not to `recent`, `enrich` or discovery.
- Output is longer when there are open findings.

## Known limits

- A CVE that CISA lists but that matched nothing installed (`unmatch`) still has a table row only.
- Findings recorded before 0.4.0 have no EPSS, SSVC or technique lines. `lattice-scan --cve CVE-... --refresh` reads it again and saves them.
- `enrich`, `recent` and `project` are unchanged.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
