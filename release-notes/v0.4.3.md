# lattice-scan 0.4.3

**The default scan shows everything it knows, `--refresh` runs the scan, ordinary words no longer cause false matches, a new `posture` command shows what a host exposes and runs, and the tool has had a self-audit.** What is sent to Lattice (CVE ids and a key if set) is unchanged; `posture` sends nothing.

## Highlights

- **`--refresh` runs the scan.** It collects the inventory again, shows its totals, then does what the same command does without it (the daily list when no id is given). Before, it stopped after the inventory. `--refresh --inventory` keeps the old behaviour: inventory only, no network call. The skill and the manual use that form for an inventory-only run.
- **The default scan keeps the findings still open from earlier runs.** When nothing on the day's list matched, it printed only the list's rows and dropped them. It now lists every open finding with its saved detail.
- **Every row has a detail block.** For a CISA-listed CVE that matched nothing: dates, CVSS, EPSS, ransomware flag and why nothing matched (the words it needs and which this machine has). For a watched critical CVE: why it is watched. Each ends with `lattice-scan --cve ID` for the full Lattice detail. No extra call is made.
- **A CVE you name that CISA does not list is related to what is installed.** The words of its description that are also installed on the host or in an opened image are listed (for the OpenSSH on musl libc flaw: openssh on the host, musl in the Alpine images), with whether any opened image has all of them and the version text of the description. It is a lead for a person to read, not a match.
- **Ordinary words no longer match unrelated packages.** "Docs Server", "Remote Support", "Software Center", "Media Server" and "WP Libre Form" matched `gnome-user-docs`, `armv8crc-support`, `gnome-control-center`, `media-player-info` and two unrelated packages. A product made only of ordinary words now matches only when the vendor is also installed, and a product of several words matches a host package only when all its words are in one installed name or the vendor is installed. Google Brotli, ISC BIND and the kernel still match.
- **New: `lattice-scan posture`.** What this host exposes and runs, beyond what is installed. Quick: listening ports (all interfaces, loopback only, one address) with the owning process, package or container image; the host firewall; the SSH server settings; the running services and whether a package owns each program. `--deep` also reads every process it may (program in a temporary folder, deleted while running, memory only, owned by no package, with outbound connections of those) and persistence points (`ld.so.preload`, extra uid 0 accounts, cron and setuid files no package owns). It follows the user who runs it: as root it reads firewall rules, `sshd -T` and every process; otherwise it lists what it could not read. It never runs `sudo`. It reports signals for a person to read, each saying why it can be harmless; it does not detect incidents. Read only, nothing sent, command line arguments never recorded.
- **Self-audit (`docs/SELF-AUDIT.md`).** No runtime dependency, no maintainer scripts in the `.deb`, bandit 0 high. Fixed: a `pom.xml` with entities or a DOCTYPE is skipped; manifests over 5 MB are skipped and named; text from an image or firmware has control characters replaced before printing; an RPM database from an image is opened query-only with `trusted_schema` off; an image reference starting with `-` is not passed to docker; the release builds with setuptools 84.1.0 or later.
- **A wider table.** The CVE table and the project report use up to 160 columns on a wide terminal (they stopped at 110).

## What changes for you

- `lattice-scan --refresh` now reads namiq.io's recent list (a request with no id and nothing about the host) and may read matching CVEs from Lattice. Use `--refresh --inventory` for the inventory alone.
- Findings recorded by earlier runs stay until you close them. A name collision recorded before this release can be closed with `lattice-scan resolve CVE-... --status not-applicable --proof "name collision"`.
- A product that is genuinely made of ordinary words, with a vendor that is not installed, no longer matches by name alone. Use `lattice-scan --cve ID` to read it from Lattice.

## Known limits

- The list of ordinary words is short and explicit; a collision on a word not in it can still happen.
- The lead for an unlisted CVE uses the description only, and the words are matched against package names; it can miss a product named differently.
- `posture` is a first look: a process that hides from the user it runs as is out of its reach; as a normal user it cannot see other users' processes or the firewall rules. Windows and macOS are not covered.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
