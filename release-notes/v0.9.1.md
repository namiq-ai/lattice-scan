# lattice-scan 0.9.1

**A host scan now matches installed packages to exploited CVEs by package identity where it can, instead of by words. It finds things it missed and stops matching things it should not have.**

## What is new

- **Matching by package identity.** namiq.io publishes a signed list of the package identities each CISA-listed CVE affects (about 400 of the roughly 1,800 CVEs on CISA's list have one). Where the list covers a CVE, an installed package matches when the source package it was built from is one the list names, on the host and inside container images. On a test host this found WebKitGTK (CVE-2024-27834), which no package name gave away, and matched Chromium to the real `chromium-common` inside an image instead of to `node-electron-to-chromium`.
- **Leads, not candidates, for word matches.** Where the list covers a CVE and a package only shares a word with the product, the result is `LEAD`, with no version range compared.
- **Component rules.** Where the list says which part of a product a flaw is in, a host whose package database shows that part is not installed is not a candidate. The first entry: CVE-2026-123158 is in `sshd`, so `openssh-client` alone is ruled out.
- **`--python`.** Reads pip, uv and conda installs in system, user and home-folder virtual environments, from their metadata files only, and matches them as `pypi:NAME`. A pip-installed wheel named on CISA's list (for example `brotli`) is found.

## What changed

- The inventory records which source package each binary package came from (dpkg, rpm, apk). It stays in the local `inventory.json`.
- Each host scan downloads the identity list at most twice a day. Nothing of yours is sent with it, and it holds names only, never version data. A list that is unsigned, signed by an unknown key, older than one already accepted, too large, or carrying version data is refused, and matching falls back to names. Offline, the last verified copy is used, or the copy bundled in this release, with its age printed. `LATTICE_SCAN_IDENTITIES_URL=0` turns it off.
- Where the list has no row for a CVE (most vendor and appliance products: Microsoft, network devices, and so on), matching by names is unchanged. The kernel and the Node runtime are still matched by the running kernel and `node -v`.
- The local host report adds what listens and runs on the machine when a posture reading exists, and shows each item's installed version.

## What is not in this release

- The version verdict is unchanged: it still compares upstream numbers with NVD's ranges. A distribution that backported a fix under the same upstream number can still read as in range. Judging by the distribution's own fixed version needs a server change that is not switched on yet.
- Ubuntu, Go, NuGet, Packagist and RubyGems identities are not in the list yet. Ubuntu hosts match through Debian's source names, which mostly agree.
- `--python` does not read Node, Java or bundled libraries, and does not look outside the home folder for virtual environments (use `--python-path`).
- No verdict is a finding. A result is a lead for a person to read.

## Install and verify

`pip install --upgrade lattice-scan` (or the apt package, or the Claude Code plugin). `lattice-scan --version` prints 0.9.1. Check the checksums in `SHA256SUMS` against the release assets. A host scan prints `[host] identity list generation N, CISA as of DATE, ... CVEs with package identities`; `lattice-scan --python --refresh --inventory` prints how many Python packages it read and sends nothing.
