# lattice-scan 0.2.2

**One result table, with the facts you decide on.** This release changes only what the host check prints. It does not change which ids are sent to Lattice, what a key can do, or the records on disk (two fields are added to new findings).

## Highlights

- **One table.** `RESULT BY CVE` now includes any open finding recorded by an earlier run, shown as `OPEN` with the date and reason it was recorded. The separate "N finding(s) not yet fixed" line is removed, because the table says it.
- **More columns:** `EXPLOITED` (CISA lists the CVE as exploited in the wild), `CVSS` (NVD score), `LISTED` (date CISA added it), `PATCH DUE` (CISA's due date, with days left or days late) and `RANSOMWARE` (`known`, `not recorded` or `-`).
- **Console-style layout,** as in `docker ps` and `kubectl get`: upper-case header, no dashed rule, one line per row, cells never wrap. Piped or redirected output keeps the whole text so `grep` and `awk` work; on a terminal the last column is cut with an ellipsis. A project report with `--width` still holds that width.

## Changed

- A script that parsed the old table header (`CISA list`, dashed rule, wrapped cells) or the "not yet fixed" line must be updated. `--json`, `--csv` and exit codes are unchanged.
- New findings store `ransomware` and `cvss`. Older findings show `-` in those columns until the CVE is read again.

## Known limits

- `RANSOMWARE: not recorded` means CISA has not recorded ransomware use. It does not mean ransomware does not use the CVE. `EXPLOITED: no` means only that the CVE is not in the graph's CISA snapshot.
- The CVE's own publication date is not shown: Lattice does not return it.
- `PRODUCT` is `-` for an open finding from an earlier run.
- A match is a candidate for a person to read, not a finding. The host check is tested on Debian-family hosts.
