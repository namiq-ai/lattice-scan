# lattice-scan 0.2.0

**New: `lattice-scan project` checks what a project declares it depends on.** Until now the tool inspected only an installed host. A project's own manifests say what it will install, and a CI runner or a developer machine has no inventory worth scanning. The host check is unchanged and still the way to check a server.

## Highlights

- **A project check that installs and runs nothing.** It reads Python (`requirements*.txt`, `pyproject.toml`), JavaScript (`package.json`, `package-lock.json`), Java (Maven, Gradle, lockfile, version catalog), Rust, C and C++ (CMake, Conan, vcpkg), Make, and containers (`Dockerfile*`, compose files).
- **Only a written-down version counts.** A range, a minimum, a caret requirement, a floating tag or a branch is `undetermined`, never `outside-range`. Lockfiles pin what manifests only range.
- **A report for a person, and output for scripts.** The console report has a summary table, findings with file and line, CISA's dates in plain words, the version check and the required action. `--format csv` or `--csv FILE` writes fixed columns; `--format json` or `--json FILE` carries everything.
- **Exit codes for a pipeline.** 0 done, 1 `--fail-on` matched, 2 bad input or no confirmed key, 3 stopped part-way.
- **A manual page.** `man lattice-scan` is installed by the `.deb`.

## Who can scan what

- Without a key, name the CVEs: `lattice-scan project . --cve CVE-2026-46300,CVE-2021-44228` (at most 40 a run).
- With a key whose owner has confirmed their email, `--kev-catalogue` lets CISA's catalogue choose the ids. An unconfirmed key is refused before any id is read.
- Only CVE ids (and your key) leave the machine. Package names and versions stay local.

## Try it

```bash
pipx install lattice-scan            # or: pip install lattice-scan
lattice-scan project . --cve CVE-2026-46300,CVE-2021-44228
lattice-scan --cve CVE-2026-46300    # the host check, on the server itself
```

## Changed

- The range check no longer discards NVD ranges because CISA and NVD name the vendor differently (Kludex and encode for Starlette, Sudo and sudo_project), and treats CISA's `Vitejs` as the npm package `vite`.
- `--cve` takes several ids separated by commas in host mode too.
- Python 3.9 and 3.10 have no `tomllib`; the tool now reads TOML dependency files itself there.

## Found by running it on six real projects, fixed before release

- A loose word match gave 75 candidate ids for one project; matching by identity gives 3.
- The same Vite CVE got different verdicts in different projects; each declared component is now judged on its own.

## Known limits

- A match is a candidate for a person to read, not a finding. A distribution can fix a CVE under an unchanged version number, and a lockfile may not be what runs.
- A package that only shares an npm scope with a product (for example `@vitejs/plugin-react` for Vite) is reported as a lead and its version is never compared. The separate `lead` verdict, which also covers client libraries such as the PyPI `minio`, is not in this release; it follows in the next one.
- The host check is tested on Debian-family hosts. On rpm and apk hosts the inventory is collected but matching is not tested.
