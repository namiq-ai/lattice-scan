# lattice-scan 0.2.3

**A narrower result table, so the part that says what matched is not cut off.** This release changes only what the host check prints, and the Claude skill's instructions. It does not change which ids are sent to Lattice, what a key can do, or the records on disk.

## Highlights

- **Shorter table.** The header is `EXPLOIT` and `RANSOM`; results read `CANDIDATE`, `RECORDED`, `unmatch`, `unlisted`, `skipped` and `OPEN`; columns are two spaces apart; `PATCH DUE` is the date only; the no-match text is `no package, snap, image or kernel matches`. An open finding from an earlier run leads with why it matched, then when it was recorded.
- **`RANSOM` is `known` or `-`.** `-` means CISA has not recorded ransomware use. It does not mean ransomware does not use the CVE.
- **Narrow terminals keep the match column.** If `MATCHED / COMPARED` would get under 45 characters, `LISTED`, `PRODUCT` and `CVSS` are hidden in turn and a note under the table says so. Piped or redirected output always has every column and never cuts a cell.
- **The Claude skill explains the table.** `SKILL.md` now describes each column, the progress lines and `--quiet`, and how to word `RANSOM -` and `unlisted` (never "no ransomware", never "safe").

## Changed

- A script that parsed the 0.2.2 table (`EXPLOITED`, `RANSOMWARE`, `no match`, `not listed`, `OPEN (open)`, `(in 19d)` after the due date) must be updated. `--json`, `--csv` and exit codes are unchanged.
- The progress lines and the project report's own table keep their wording.

## Known limits

- `CANDIDATE` is a product-name match for a person to read against the installed version. It is not a finding that the host is vulnerable; a distribution can fix a CVE under an unchanged version number.
- `unlisted` means only that the CVE is not in the graph's CISA snapshot.
- The CVE's own publication date is not shown: Lattice does not return it. `PRODUCT` is `-` for an open finding from an earlier run.
- The host check is tested on Debian-family hosts.
