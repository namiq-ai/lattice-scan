# lattice-scan 0.4.5

**The report no longer keeps false findings open, counts ages from today, and separates what this run read from what was recorded earlier.** What is sent to Lattice (CVE ids and a key if set) is unchanged.

## Highlights

- **Open findings are re-checked on every run.** A finding made by an older, looser matcher used to stay `OPEN` for ever: one host carried seven false ones (BeyondTrust, Siemens, ONLYOFFICE and four Plex CVEs, each matched on an ordinary word such as `support` or `media`). A finding the current matching no longer produces is now **withdrawn** with the reason recorded. It shows once in a `WITHDRAWN` block, no longer counts as open or as touching the host, and `lattice-scan list` still shows it. New findings store the vendor and product they matched on and are matched again as they are. Older ones stored only a title and a reason, so for those only the one rule that changed is applied: a product made of ordinary words needs its vendor installed.
- **Today and the past are separate.** A second table, `STILL OPEN FROM EARLIER RUNS`, lists findings recorded before today, apart from the table of what this run read. "0 may match" is no longer followed by a list of `OPEN` rows with no heading.
- **Ages are counted from today.** A saved finding used to show the "days ago" and "overdue by" of the day it was recorded.
- **A finer reading of a name match**, in the earlier-findings table and as an `assessment:` line in the detail: `OUTSIDE RANGE` (the installed version is outside every NVD range), `LIKELY FIXED` (inside the upstream range, but the version has a distro revision and the package's own changelog names the CVE), `VERIFY` (a kernel whose upstream number is in range but which is a distro or vendor build). Nothing is closed by it: a person reads the evidence and records the outcome with `resolve`.
- **A deep scan is no longer lost to the next quick run.** A complete `--deep` scan is kept (`deep-images.json` in the records folder, with each image's id). A later quick run reuses it for every local image whose id is unchanged, up to 30 days old, and opens only what is new or changed. `--refresh` or `LATTICE_SCAN_DEEP_CACHE=off` opens every image again; `LATTICE_SCAN_DEEP_CACHE_DAYS` sets the age limit.
- **The result row of a named CVE that CISA does not list** now says `lead` when its description names something installed (for example `openssh on the host`, `musl in 9 opened images`, and whether any opened image has all of them), instead of only `unlisted`. It is a lead for a person to read, not a match.

## What changes for you

- On the first run after the upgrade, findings the current matching no longer produces are withdrawn and listed once. Check the `WITHDRAWN` block; nothing is deleted.
- Open findings appear in their own table below today's. The records files keep the same format; new fields (`vendor`, `product`) are added to new findings.
- A quick scan after a deep scan prints one stderr line saying how many images came from the deep scan.

## Known limits

- `LIKELY FIXED`, `VERIFY` and `OUTSIDE RANGE` are readings of local evidence (installed version, NVD ranges, the package's own changelog). The tool does not look up Ubuntu, Debian or vendor patch status.
- Withdrawal of a finding recorded by an older version relies on its title and reason; a finding from before that changed more than the ordinary-word rule is not withdrawn.
- A reused deep reading describes an image as of the deep scan; it is replaced when the image id changes, or after 30 days.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
