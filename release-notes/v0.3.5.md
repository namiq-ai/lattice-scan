# lattice-scan 0.3.5

**The OpenAI plugin package names its real publisher, and the open-list wording no longer claims more than the list knows.** This release changes the package built for OpenAI's plugin directory and some wording in the tool's help and manual. What the tool does, the Claude skill's text and what leaves the machine are exactly as in 0.3.4.

## Highlights

- **Publisher: Hung Le.** OpenAI requires a plugin to come from a verified person or organisation. The identity verified on the OpenAI account is an individual, so the package's listing (`developerName`) and its author now say Hung Le, where 0.3.4 said NamiQ LLC. The website, support, privacy and terms links are still the project's own pages at namiq.io, and the description says that the tool is open source under Apache-2.0 and that the Lattice service it reads is the one at namiq.io.
- **Wording about the open list.** The help for `recent --open`, the manual and the 0.3.1 release notes described the open list as covering machines that had not yet been patched. The list cannot know anything about a machine: it says that CISA's due date has passed, and now says exactly that. The feed's own note on namiq.io was corrected the same way, and the same words are kept out of every published text by a test.
- **No email in the package.** The manifests no longer carry an email address; support is the contact page.
- **A check for it.** `packaging/check_openai_plugin.py`, which the release workflow runs, now refuses a package whose listing publisher differs from its author.

## Known limits

- The package is not listed in OpenAI's directory. Submitting it needs OpenAI's review, and their upload page has returned an error for this account; nothing here says otherwise.
- The package bundles the `lattice-scan` script. OpenAI's published rules do not say whether bundled scripts are allowed, so the checker reports a warning for it and only OpenAI's review can answer.
- `recent` lists what was recently added, and matches by product name. An empty or all-`unmatch` result is not the same as safe.
- The host check is tested on Debian-family hosts.
