# lattice-scan 0.9.2

**A host scan can now ask, with your consent, for the distribution's own verdict on the packages it matched, so a fix your distribution backported shows as FIXED instead of a false alarm. Each release now states how often the matcher is right on an open set of test cases.**

Corpus: precision 0.86, recall 1.00 on 12 synthetic host cases (without the distribution verdict: 0.67, 0.67)

## What is new

- **The distribution's own verdict, after you say yes.** When packages on your machine match a CVE by package identity, the scan asks once whether to send, for those packages only, the source package name, ecosystem, version and OS release (for example `brotli`, `deb`, `1.1.0-2+deb13u1`, `Debian 13`). Lattice answers from the distribution's or registry's own fixed version. A fix Debian or Ubuntu backported under an unchanged upstream number shows as `FIXED`, not `CANDIDATE`. A pip wheel that NVD's range misses (brotli 1.2.0; the registry's fix is 1.2.1) shows as in range. Unmatched packages, your host name, addresses, paths and package list are never sent. `d` at the question lists every item; `a` remembers "always"; with no terminal nothing is sent unless `--yes`. `LATTICE_SCAN_ITEM_VERDICT=off` never asks.
- **Ubuntu's own fixed versions.** Lattice now holds Ubuntu's per-release fixes beside Debian's, and never mixes the two.
- **`--node`.** Reads Node packages installed globally (`npm install -g`, nvm) and their dependencies from `package.json` files only, and matches them as `npm:NAME`.
- **What the run covered.** A host scan and `recent` end with WHAT THIS RUN COVERED: CVEs read, results by kind, the identity list used and how much of CISA's catalogue it covers, the items read by source, and what a clean result does not speak for. `--format json` carries the same object as `receipt`.
- **A precision and recall gate.** Twelve synthetic host cases, each copied from a real case (a client-only OpenSSH, a JavaScript package named after Chromium, a backported fix, a pip wheel, a vendor product with no identity). The figures above come from them; a drop fails the build, and every release must state them.
- **Google Chrome.** `google-chrome-stable` is matched to Chromium's flaws through a reviewed alias.
- **`posture`** also looks for secret-looking values (a key, token or password) on the command lines of programs it may read and in your shell history. It shows the kind of value, the place and a count, never the value, and sends nothing. A harmless test value matches too: it is a lead.

## What changed

- The kernel rule no longer matches when an imported inventory has no kernel version.
- The bundled identity list is generation 6 (406 CVEs with package identities).
- Internal and switched off: plumbing for a mailed report (a confirmation link first, then the record, after a person reviews it). Nothing in this release offers to mail anything.

## What is not in this release

- **Coverage.** About 23% of CISA's exploited CVEs have a package identity. The other 77% (Microsoft, network devices, most vendor products) are still matched by names, with the false matches that brings: the one remaining corpus error is a vendor product matched by a shared word.
- The server's Ubuntu verdict depends on an update to Lattice that is being rolled out; until it is live, Ubuntu packages come back "undetermined" rather than borrow Debian's fixes.
- Scoped npm packages (`@org/pkg`) and Maven ids are matched but not sent for the distribution's verdict (the item rules allow no `@`, `/` or `:`); they keep the upstream comparison.
- Twelve hand-written cases are a regression gate, not a benchmark. No other tool has been run on them.
- No verdict is a finding. A result is a lead for a person to read.

## Install and verify

`pip install --upgrade lattice-scan` (or the apt package, or the Claude Code plugin). `lattice-scan --version` prints 0.9.2. Check the checksums in `SHA256SUMS` against the release assets. `python3 packaging/corpus_score.py` in a source checkout prints the figures above. A host scan ends with WHAT THIS RUN COVERED; if packages matched by identity, it asks before sending anything for the distribution's verdict.
