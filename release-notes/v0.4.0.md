# lattice-scan 0.4.0

**A host-scan candidate now says how urgent it is and what it is.** Until now a candidate showed CISA's dates, the ransomware flag, a version check and the changelog check. Since Lattice began serving one node read without a key, the tool uses it to add the context a person otherwise looks up by hand. What is matched, how versions are compared and what leaves the machine are as in 0.3.6.

## Highlights

- **A "why it matters" block under each candidate:** a priority (`fix first`, `fix soon` or `read`) with the reasons it rests on; the EPSS score and percentile (FIRST); CISA's SSVC assessment; the weakness (CWE); the start of NVD's description; the ATT&CK techniques the graph links to the CVE, marked "likely" when the graph inferred the link; the first unaffected upstream version NVD lists for the product; and up to three references.
- **Highest priority first.** Candidates are printed in the order `fix first`, `fix soon`, `read`. `lattice-scan impact CVE-...` shows the saved block again with no new call.
- **The priority is the tool's reading, not a verdict.** `fix first` means CISA records ransomware use, or CISA's SSVC says exploitation is active and automatable, or CISA's patch-due date has passed. `fix soon` means none of those and EPSS is 0.5 or more. `read` is everything else. The output says it is not a verdict.
- **The skill** tells an agent to quote these lines with their source, say "likely" for inferred techniques, not to reorder or drop candidates, and not to fill in missing context from memory.

## What changes for you

- **One more call per candidate**, counted against the keyless limit (5 a minute, 20 reads an hour, 60 a day). Only candidates trigger it: a run over 10 ids with one match makes 11 calls. A repeat run reuses the saved block and makes no second detail read.
- **Only CVE ids and the node ids Lattice returned leave the machine.** The inventory still does not.
- Output for a candidate is longer. `--format csv` and `json` for `project` are unchanged.

## Known limits

- If Lattice refuses the detail read or has no links for the id, the candidate is printed as in 0.3.6 and one line on stderr says so.
- The description is cut at 300 characters, and may stop mid-sentence.
- The first unaffected version is an upstream number from NVD. A distribution can fix a CVE under the same number, so it is not an instruction to install that version.
- The context block is not in `project` mode yet.
- The tool still does not detect incidents or decide whether a host is affected. A match is a candidate for a person to read.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
