# lattice-scan 0.5.0

**One discovery command for a host and for a project, with no key, and a count-only audit of old software.** `lattice-scan --discover` now works on the host the way `project --discover` does, over a daily, weekly, monthly or open window. `--discover --all` matches every CISA-listed CVE in a signed index against the machine, locally, and prints counts. The bare command is now `--discover --weekly`.

## What is new

- **New:** `lattice-scan --discover` on the host needs no key. It is the same engine as `recent`, with `--daily`, `--weekly` (the default), `--monthly` and `--open`; `recent --monthly` is the same thirty-day list that `recent --all` has always read.
- **New:** `lattice-scan --discover --all` and `lattice-scan project . --discover --all` match the whole signed exploited index (every CISA-listed CVE, with NVD's version ranges) against the host or the declared dependencies. Nothing is sent and nothing is read from Lattice. The free output is statistics only, in the console, `--format json|csv` and `--json FILE`: counts by verdict (in-range, undetermined, outside-range) and by the year CISA added them, a count under 3 shown as `<3`, no CVE id and no product name.
- **New:** `lattice-scan index` fetches, checks (sha256, a pinned Ed25519 signature, generation, age) and caches the index. A bad signature, a lower generation or a copy older than 14 days is refused for `--all` (exit 2); an unreachable index with no cache is exit 3.
- **New, internal:** a verify-only Ed25519 in pure Python, so the tool still needs only the standard library.

## Who can use it and how

Anyone, with no key. `lattice-scan --discover --all` is for old or neglected machines, where the recent list cannot help. A count is a lead for a person to check, never a verdict that the machine is vulnerable.

## What changed

- Running `lattice-scan` with no arguments is `--discover --weekly` (it was `recent --daily`).
- One `--max-read` for every command: 20 reads from Lattice without a key, 200 with one (`project` was 40; `recent` and the bare run differed). Every id is still matched against the host locally; matches over the cap are listed as skipped, not dropped.
- `recent --all` is unchanged. Exit codes 0, 1, 2 and 3 are unchanged.

## Known limits

- `--all` prints counts only. Name-level matching of old CVEs is noisy (on one development host: 14 in-range and 77 undetermined of 1,769), which is one reason it does not list them.
- Matching is still by product name; matching by index aliases comes later.
- The index is as fresh as namiq.io's knowledge refresh; it carries its own date, and the tool prints it.

## Install and verify

`pip install lattice-scan==0.5.0`, or `uv tool upgrade lattice-scan`; the signed apt repository at https://namiq.io/apt after the repository update; assets on the release: `lattice-scan.pyz`, the `.deb`, the wheel, the Claude and OpenAI plugin zips and `SHA256SUMS`. Check with `lattice-scan --version`.
