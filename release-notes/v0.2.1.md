# lattice-scan 0.2.1

**See what the scan is doing, read the result as a table, and know where the detail is.** This release changes what lattice-scan prints and how it judges a package that only looks like the product. It does not change which ids are sent to Lattice or what a key can do.

## Highlights

- **Progress, on by default.** On stderr, one line per step: each part of the host as it is collected (packages and which package manager, snaps, running container image names, kernel) with counts; each project file read with its kind (`Python requirements`, `JavaScript lockfile`, `Java Maven file`, `Docker image file` and so on) and its component count; then for each CVE `[n/N]`, "asking Lattice (only this id is sent)", what CISA lists, what it was compared with, and whether anything matched. Package names and versions are never printed. `--quiet` (`-q`) or `LATTICE_SCAN_PROGRESS=0` turns it off.
- **A result table.** The host check and the console project report print `RESULT BY CVE`: the CVE, whether CISA lists it, the product, the result (`CANDIDATE`, `no match`, `not listed`, `skipped`, or the project verdict) and what matched or was compared. `--json` output carries the same rows as a `checked` list per project.
- **The detail files are named.** A `DETAILED RESULT FILES` section says where the full detail is: for the host, the private records folder and what each file holds (`findings.jsonl`, `scan.log`, `inventory.json`, `runs.jsonl`), with the `list`, `impact` and `resolve` commands; for a project, the `--csv` and `--json` files you asked for, or how to ask for one.
- **A new verdict, `lead`.** A package that only shares a scope or name with the product (`@vitejs/plugin-react` for Vite), or is its client library (the PyPI `minio` for the MinIO server), is a `lead`. Its version is never compared with the product's ranges, it has its own summary column, and it ranks below every real comparison, so it no longer inflates the in-range or undetermined counts.

## Changed

- stderr now carries progress lines by default. Standard output keeps its form, with the result table and the detail-files section added to the host check and the console report. `--format csv`, `--format json`, exit codes and the records on disk are unchanged. A script or CI job that expects an empty stderr should pass `--quiet`.
- A JSON result gains `checked` per project, and a finding may carry `"verdict": "lead"`. Code that reads the JSON should accept both.

## Known limits

- A match is a candidate for a person to read, not a finding. A distribution can fix a CVE under an unchanged version number, and a lockfile may not be what runs.
- The progress and tables describe what lattice-scan did. They do not mean a host is safe: a CVE that is `not listed` is only not listed in the graph's snapshot.
- The host check is tested on Debian-family hosts. On rpm and apk hosts the inventory is collected but matching is not tested.
- The project check does not read `composer.json`.
