# lattice-scan 0.9.3

**A host scan now finds a Node runtime bundled inside another package and checks it against CISA's exploited CVEs, and says why each result it could not judge is undetermined. Word-only name matches are reported as leads instead of candidates.**

Corpus: precision 1.00, recall 1.00 on 12 synthetic host cases (without the distribution verdict: 0.80, 0.67)

## What is new

- **Node bundled inside packages.** Some packages ship their own Node binary (Playwright's `driver/node`, a vendored `node`). No package manager lists these, and `node -v` never shows them. With `--python` or `--node`, the scan looks at a few fixed places inside the folders those flags already read, takes the version from the release address the official build carries as text (`nodejs.org/download/release/vX.Y.Z`), and checks it against NVD's Node.js ranges. The file is never run, only files named `node` that start like an executable are read, and at most 40 are read. On the host this was found on, it was the only exploited exposure every other reader missed: Node 24.17.0 inside a pip-installed Playwright, below the fix in 24.22.1 (CVE-2026-111497). A Node from the distribution's own `nodejs` package is left to that package's verdict, because it uses the system's libraries.
- **Why a result is undetermined.** WHAT THIS RUN COVERED now breaks the undetermined results down by cause: the distribution's data does not cover that release, the kernel, a match by name only, no version range, or still being investigated. It also names the data the run used: the graph snapshot and the index date. `--format json` carries the same in `receipt.undetermined` and `receipt.data`, and each `versionCheck` carries Lattice's `reason` code when it gives one.

## What changed

- **Fewer false matches on partial names.** A product word found only inside a longer package name is a `LEAD`, not a candidate: Ivanti "Pulse" no longer matches `libcanberra-pulse`. A vendor word inside another package's name is treated the same way. When the identity list is in use, a `lib…` package that matches only by name is a lead too. A real library CVE (Brotli, libwebp) has an identity row and matches through it first. With no list (offline, or a self-hosted server) the library name still counts.
- **Bundled identity list.** Generation 8, 411 rows, now with Debian and Ubuntu package names taken from the distributions' own security data.
- **Corpus.** The case for a word inside a longer package name is now a correct non-match. The figures above come from this build.
- **Corrected example.** The README and the 0.9.2 notes gave the brotli 1.2.0 wheel as a version NVD's range misses. It is not: NVD lists a second range that covers it. The real example of the registry's verdict helping is Pillow 12.3.0 against CVE-2023-4863.
- Internal and switched off: a terminal flow that gives a person with no key a free key after they type `agree` to the beta terms and prove their mailbox. Nothing in this release offers it.

## Also new, without upgrading

These come from the Lattice server, so every version of the scanner gets them:

- Answers for each package's own OS release, from Debian's security tracker and Ubuntu's VEX data. A flaw a release fixed at an older version is reported as fixed in an earlier release instead of "no data for this release". On the host above, undetermined results went from 147 to 19.
- An answer no longer stops after 20 CVEs for a package with many (WebKitGTK, Chromium).

## What is not in this release

- **Coverage.** About 23% of CISA's exploited CVEs have a package identity. The rest (Microsoft, network devices, most vendor products) are still matched by names.
- **Releases the distributions' data does not cover** stay undetermined. On the host above, 17 of the 19 remaining undetermined results are of this kind.
- **Other bundled runtimes.** Only Node is read. A Python, Java or Electron runtime bundled inside a package is not.
- **Node builds without the release address.** A Node built from source, or one whose release address was removed, is not recognised.
- Windows and network devices are not read.
- Twelve hand-written cases are a regression gate, not a benchmark. No other tool has been run on them.
- No verdict is a finding. A result is a lead for a person to read.

## Install and verify

`pip install --upgrade lattice-scan` (or the apt package, or the Claude Code plugin). `lattice-scan --version` prints 0.9.3. Check the checksums in `SHA256SUMS` against the release assets. `python3 packaging/corpus_score.py` in a source checkout prints the figures above. A host scan with `--python` or `--node` lists a bundled Node under the items read, and WHAT THIS RUN COVERED ends with the breakdown of undetermined results.
