# lattice-scan 0.8.0

**The tool keeps working when the network is down, and it checks that namiq.io's recent-CVE list is genuine.**

## What is new

- **No network, no stop.** A refused or unreachable connection is tried once (not once per CVE id, and without the repeated waits). `recent`, `enrich` and the host scan then answer from what an earlier run saved: the recent list (now saved on every successful read) and each CVE answer, at any age. The first line says `OFFLINE:` and how old the data is, and warns past 30 days. A saved "not listed" is printed as `not listed as of DATE, not rechecked` and is never the same as clear. An id with no saved answer is listed as not read, and only those make the exit code 3. A run with the network down now ends in about a second instead of 8 to 22 seconds.
- **The recent-CVE list is signed.** The tool fetches `recent.json.sig` and `recent.json.cert` (two small static files beside the list; nothing of yours is sent) and checks them with a root public key built into the tool, using a verify-only Ed25519 written in this package (standard library only). A good check prints `[feed] signature verified`. A list with no signature (a self-hosted server, for example) is read and labelled `not signed`. A signature or certificate that is offered and wrong, expired or revoked stops the read with the reason, and the list is not used. You can check the same signature with OpenSSL once you have the public key.
- **A "scan ran" note.** After a run that read from Lattice or the recent list, the tool tells namiq.io once that a scan ran, so we can count scans (downloads cannot tell us). The whole of it is the command (such as `recent`), how it ended (`ok`, `matched`, `stopped` or `failed`) and the number of reads as a band (such as `6-20`), plus the UTC day if the note was kept while you were offline and sent later. Never a host name, package, CVE id, path, address or key. The first run prints a note saying so. If namiq.io cannot be reached, the note is kept in a small file in the cache folder (50 notes at most, 30 days at most) and sent with the next run that is online. Turn it off, and keep nothing for later, with `LATTICE_SCAN_NO_REPORT=1`. It is also off for a self-hosted Lattice or list address.
- `LATTICE_SCAN_TEST=1` marks the tool's user agent as a test run so our own runs can be left out of the website's counts. Nothing else is added to a request.

## What changed

- When Lattice cannot be reached, `enrich` now says so and tells you to check the network. It used to say the keyless allowance was used up and suggest asking for a key. The exit code (3 when an id is unread) is unchanged.
- `SECURITY.md` now lists the two further requests to namiq.io (the list with its signature and certificate, and the "scan ran" note) next to CVE ids and the key.

## What is not in this release

- There is no data packaged in the tool for the case where nothing was ever saved: with no network and no saved answer for an id, that id is still unread and the run exits 3. A packaged, signed snapshot is planned, not built.
- A saved copy records whether it was verified, but the tool does not yet treat a verified saved answer differently from an unverified one.
- Revoking a certificate (raising the lowest accepted serial) reaches only installs that have upgraded, and replacing the root key means a new release; older installs read the list as unverified or refuse it until they upgrade.
- `DO_NOT_TRACK` is not read. The switch for the note is `LATTICE_SCAN_NO_REPORT=1`.
- No verdict is a finding. A result is a lead for a person to read.

## Install and verify

`pip install --upgrade lattice-scan` (or the apt package, or the Claude Code plugin). `lattice-scan --version` prints 0.8.0. Check the checksums in `SHA256SUMS` against the release assets. Check the signature behaviour with `lattice-scan recent` (the first line on stderr says `signature verified`).
