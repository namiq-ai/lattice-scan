# lattice-scan 0.6.0

**A finding now says what the machine does with the software, and a run says what changed since the last one.** Each host candidate prints an `exposure:` line, host scans keep local snapshots and print what is new, changed or gone, and `posture --attack` names the ATT&CK techniques a signal relates to. This release also carries 0.4.10 and 0.5.0, which were prepared but never published: read `release-notes/v0.5.0.md` for the single discovery command (`--discover`, `--discover --all`) and the signed exploited index.

## What is new

- **New:** every host candidate prints an `exposure:` line, a fact read from this machine's listeners and services: listens on all interfaces (address, port, owning package), loopback only, service running with no listener, installed with no service found, or inside an image. Candidates of the same priority are listed with the more exposed first.
- **New:** `--exposed` lists only candidates whose package owns a listener or runs as a service; the rest are counted and still recorded. `--fail-on exposed` exits 1 only for an in-range candidate that listens on all interfaces.
- **New:** every host scan stores a private local snapshot (listening ports, running services, effective SSH settings as root, persistence entries when deep, open findings), keeps the latest 30, and prints what is new, changed or gone, with the day a new finding was first found. `posture --since last` does the same for the running layer; `--format json` carries it as `change`.
- **New:** `posture --attack` names the ATT&CK techniques each signal relates to. The table is one signed file namiq.io publishes beside the exploited index; the tool downloads it (hash and signature checked, a lower generation refused, the verified copy used offline) and carries no copy. Every posture signal now has a stable code, for example `ssh.password-auth`.
- **New:** a host scan ends with a COVERAGE line: what the running layer covered, and how many running programs and persistence entries belong to no package and so cannot be matched by name.

## Who can use it and how

Anyone, with no key. Run `lattice-scan --discover --exposed` to see only software that listens or runs here. Run `lattice-scan posture --since last` after changing a machine, and `lattice-scan posture --attack` to see technique ids.

## What changed

- `--fail-on` accepts `exposed`. Everything else about exit codes (0, 1, 2, 3) is unchanged.
- Host scans now read the listeners and services once to label candidates (read only, nothing sent) and write a snapshot to the records folder.

## Known limits

- An exposure label is a local fact. It never says the software is reachable from the internet: NAT, upstream firewalls and cloud rules are unknown, and without root the firewall rules are not read.
- Enabled-but-stopped services are not covered; the label is "service running", and the coverage line says what was not read.
- A technique is a reason to read a signal, not a sign that an attack happened. The signal-to-technique table is a proposal that a reviewer must confirm before a paid report relies on it. `--attack` works only once namiq.io serves the table; until then it stops with exit 3.
- Technique names are not shown, only ids. `--exposed` applies to the host, not to `project` or `--discover --all`.

## Install and verify

`pip install lattice-scan==0.6.0`, or `uv tool upgrade lattice-scan`; the signed apt repository at https://namiq.io/apt after the repository update; assets on the release: `lattice-scan.pyz`, the `.deb`, the wheel, the Claude and OpenAI plugin zips and `SHA256SUMS`. Check with `lattice-scan --version`.
