# lattice-scan 0.4.9

**Check a project against recent exploited CVEs with no CVE ids and no key, and use the results in scripts.** `lattice-scan project . --discover` reads namiq.io's public list of recent exploited CVEs, keeps the ones whose product a declared dependency matches, and reads only those ids from Lattice. The host check, `recent` and `enrich` can now print their result table as JSON or CSV, and exit codes mean the same in every command.

## What is new

- `lattice-scan project . --discover`: no `--cve`, no `--kev-catalogue`, no key. The window is the last thirty days by default; `--daily`, `--weekly`, `--monthly` and `--open` choose another. The list is a plain request that carries nothing from your project; only CVE ids leave the machine, and only for products a dependency matches. The "nothing to check" message now names `--discover` first.
- `--fail-on never|in-range|candidate` on the host check and on `recent`: exit 1 when a candidate (or one whose version check says in-range) is found. The default is `never`.
- `--format json|csv` and `--json FILE` on the host check, `recent` and `enrich`: the RESULT BY CVE table as one JSON document (`lattice-scan-result/1`, with the exit code and counts by result) or CSV with a header row, and nothing else on standard output. `--json FILE` is written with mode 0600 because it names the host's software. The console output is unchanged.

## What changed

- **Exit code.** A host check or `recent` that Lattice stops part-way (limit reached, unreachable, refused) now exits **3**, as `project` and `enrich` already did. Exit 1 is kept for a `--fail-on` match. A script that tested for exit 1 after a stopped run must test for 3.
- The skill text no longer says the host check takes `--format`; it now does, and a test fails when the README or the skill text shows an option the program does not define.

## Who can use it and how

Anyone with the tool. Without a key, `project --discover` reads at most 40 ids a run, inside the keyless allowance; a key raises that.

## Known limits

- `project --discover` is a name match against what the project declares. A declared version is not a deployed version, so a result is a lead for a person to read, never "vulnerable" or "safe".
- The list covers the last thirty days. An older exploited CVE is found only if you name it (`--cve`) or give a catalogue (`--kev-catalogue`).
- `--discover` on the host check still needs a key; use `lattice-scan recent` for a keyless host check.
- JSON and CSV carry the result table only; the per-finding detail files are unchanged.

## Install and verify

`pip install lattice-scan==0.4.9`, or `uv tool upgrade lattice-scan`; the signed apt repository at https://namiq.io/apt after the repository update; assets on the release: `lattice-scan.pyz`, the `.deb`, the wheel, the Claude and OpenAI plugin zips and `SHA256SUMS`. Check with `lattice-scan --version`.
