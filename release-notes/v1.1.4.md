# lattice-scan 1.1.4

**The 1.1.3 changes, published, and a fresh offline copy of the identity list.**

Corpus: precision 1.00, recall 1.00 on 12 synthetic host cases (without the distribution verdict: 0.80, 0.67)

## What changed

- The identity list bundled in the release is now generation 35 (CISA catalogue as of 18 November 2026, 415 rows). 1.1.3 carried generation 8 (10 November). The bundled copy is used only on a first run when namiq.io cannot be reached and nothing is cached; it is verified at load time exactly like a downloaded copy, and the tool says its age.
- Everything in 1.1.3 is in this release: 1.1.3 was merged on 15 November but never published to PyPI or the apt repository. In short, `--report` waits up to 3 minutes for you to press Confirm and finishes by itself, and a report request is no longer refused for its coverage words. See release-notes/v1.1.3.md.

## What did not change

- The recent-CVE list. Every version reads https://namiq.io/lattice/recent.json live on each run and checks its signature; nothing of it is bundled. Its changes of 19 November reach every installed version without an upgrade: the critical list now holds records their CNA scored 8.0 or more (it was 9.0), and F5's "NGINX Open Source"/"NGINX Plus" and Oracle's "Java SE" are listed as nginx and openjdk, so `lattice-scan recent` matches the installed packages.
- Naming a brand-new CVE with `--cve` still returns no version check while Lattice holds only a bare node for it (no NVD record yet). `recent` is the way to see such a CVE while it is on the list.

## Install and verify

`pipx install --force lattice-scan` or `apt update && apt upgrade lattice-scan`; `lattice-scan --version` prints 1.1.4. Check the downloaded files against `SHA256SUMS` on the release page.
