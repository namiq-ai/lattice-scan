# lattice-scan 0.3.4

**The OpenAI plugin package, brought in line with OpenAI's published rules.** This release changes only the package built for OpenAI's plugin directory. The command-line tool, the Claude skill and what leaves the machine are exactly as in 0.3.3.

## Highlights

- **Both OpenAI manifests.** The package now carries the Codex-format manifest, `.codex-plugin/plugin.json` (skills by path, `capabilities`, starter prompts and the listing under `interface`), beside the portable `plugin.json`. OpenAI's plugin tooling treats the Codex manifest as the required structure.
- **Icon paths begin with `./`.** In 0.3.3 the icon and logo paths were written `assets/icon.png`. OpenAI's plugin-creator spec says asset paths are relative and begin with `./`, so a package built that way was likely to be refused.
- **A checker, run on every release.** `packaging/check_openai_plugin.py` checks the package against what OpenAI publishes (manifest formats, listing limits, https links, asset paths, image size, skill front matter, no hooks, apps or MCP entries, no credentials). The release workflow runs it and stops on an error. It is not OpenAI's own validator, which only runs inside their portal.

## Known limits

- The package is not listed in OpenAI's directory. Submitting it needs OpenAI's review, and their upload page has returned an error for this account; nothing here says otherwise.
- The package bundles the `lattice-scan` script. OpenAI's published rules do not say whether bundled scripts are allowed, so the checker reports a warning for it and only OpenAI's review can answer.
- `recent` lists what was recently added, and matches by product name. An empty or all-`unmatch` result is not the same as safe.
- The host check is tested on Debian-family hosts.
