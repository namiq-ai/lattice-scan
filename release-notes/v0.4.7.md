# lattice-scan 0.4.7

**A scan asks Lattice far less, and the free tier no longer runs out on the first `recent`.** What is sent to Lattice is unchanged: CVE ids, and a key if you set one. Nothing about your host leaves it.

## Highlights

- **One call per match, and ids looked up ten at a time.** Lattice's lookup now carries what you need to judge urgency (EPSS, CISA's SSVC, the weakness, the start of the description, reference links, the record's status) so the tool no longer makes a second call per match, and it can fetch up to 10 ids in one request. A 12-id scan is 3 lookups instead of 12 lookups plus 12 detail reads. This works against the live server (`lattice.namiq.io`). Against an older server nothing changes: the tool is never sent a batch it does not understand, and it reads the detail the old way.
- **A repeat run asks nothing it was just told.** Answers are kept in your cache folder for 6 hours, so running `recent` again, or looking at the same id twice, makes no call and does not wait. `--again` and `--refresh` ask again. The cache holds public graph data about CVEs, never anything about your host, and its files are readable only by you.
- **`recent` reads the most urgent ids first and says what it will cost.** Ransomware use recorded by CISA first, then patch dates already passed, then CISA's priority and the EPSS score. Before the first call it prints how many ids it will read, how many are already cached and about how long that takes. A run that is stopped has read what mattered most.
- **Pacing follows the server.** Lattice reports its per-minute limit in every answer; the tool remembers it for a week, so a limit the operator raises shortens your scans without a new release. Until told, it stays at 5 a minute. (The live free tier now allows 10 calls a minute, 60 units an hour and 200 a day.)
- **A key about to end says so.** When the key you use has 14 days or fewer left, the tool prints one line a day on stderr, with the days left. A renewal link is mailed to the address the key was issued for once the operator turns that on; the tool never opens or follows the link. Not shown with `--quiet`, and never in csv or json output.

## What changes for you

- `recent` makes fewer calls, and a second `recent` within 6 hours makes none. If you want fresh answers, add `--again`.
- The "about 20 reads an hour and 60 a day" wording is gone from the tool, the manual and the skill, because the server states the allowance in every answer.
- A new cache folder file or two appear under `~/.cache/lattice-scan/`: `read-cache.json` and `server-limits.json`. Delete them any time.

## Known limits

- A match is by product name against what is installed. The tool lists candidates for a person to read; it does not decide whether a host is affected, and it does not detect incidents.
- A batch is tried only after the first single lookup shows the server returns the new fields; the first id of a run is always looked up on its own.
- A batch that would cross the free tier's unit limit is refused whole by the server, not partly answered; the tool then carries on one id at a time and stops, as before, when the limit is reached.
- Resuming an interrupted run (reading the unread ids first next time) is not done; the 6-hour cache gives most of the benefit.
- The package is not listed in OpenAI's directory; submitting it is a separate step.
