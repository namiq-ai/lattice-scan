# lattice-scan 0.4.10

**Fixes the bundled script.** In 0.4.8 and 0.4.9, `lattice-scan.pyz` (also carried by the Claude skill and the Claude and OpenAI plugin zips) did not contain one module, so `lattice-scan inventory --share` stopped with an ImportError there. The command worked from a pip or apt install. This release bundles every module and tests the bundle by running it.

## What is new

- **Fixed:** `inventory --share` from the `.pyz`, the Claude skill and the plugin zips. `--version` and every other command were not affected.
- **Fixed:** `project` no longer reads dependency files inside a `.build` folder (build output; one project kept a third-party checkout there and its dependencies were counted as its own).
- **New, internal:** `lattice_version`, one module for version comparison (semver, pep440, dpkg, apk, rpm, maven, generic), NVD range bounds, product ids and the verdict order. The scan's behaviour is unchanged. A finding in the `project` JSON now carries its `pid`. Golden tables of 258 to 969 cases per scheme back it; dpkg and pep440 are checked against `dpkg --compare-versions` and the `packaging` library, and the other four schemes follow their own specifications with no external oracle. See docs/LATTICE-VERSION.md.

## Who can use it and how

Anyone. If you run `inventory --share` from the skill or the `.pyz`, upgrade. Nothing else changes for you.

## What changed and what did not

Verdicts, exit codes, flags and output are unchanged from 0.4.9.

## Known limits

- The matcher still matches by product name; matching by index aliases comes later.
- An external oracle exists only for dpkg and pep440 versions.

## Install and verify

`pip install lattice-scan==0.4.10`, or `uv tool upgrade lattice-scan`; the signed apt repository at https://namiq.io/apt after the repository update; assets on the release: `lattice-scan.pyz`, the `.deb`, the wheel, the Claude and OpenAI plugin zips and `SHA256SUMS`. Check with `lattice-scan --version`.
