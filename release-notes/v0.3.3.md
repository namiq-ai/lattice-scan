# lattice-scan 0.3.3

**No arguments runs the daily check, and back-to-back runs stop tripping the keyless limit.** This release changes how the tool behaves when you run it with nothing, and how it spaces its calls to Lattice. What leaves the machine is unchanged.

## Highlights

- **`lattice-scan` with no arguments** now does `lattice-scan recent --daily`: it reads the daily list of recent exploited and critical CVEs and checks the likely ones against this host. It used to print "nothing to check". The daily list is the default here because the weekly list is long, and a keyless run that has to look many entries up reaches Lattice's limit. `lattice-scan recent` on its own is still weekly, and any argument or subcommand does what it names.
- **Separate runs space themselves out.** Without a key Lattice allows 5 calls a minute, counted across everything on the machine. The tool used to space calls only inside one run, so an agent that ran it several times in a row hit `HTTP 429: Too many keyless requests` on the sixth call. It now remembers when it last called, in a small file in your cache folder (`~/.cache/lattice-scan/pace.json`, times only), and waits when it has to, with a line on stderr.
- **A 429 is waited out.** If Lattice still says "retry after N seconds", and N is about a minute or less, the tool waits that long and tries again, twice at most. A longer wait (the hourly or daily limit) still stops the run and lists what was not read, as before.
- **One record per finding.** Two runs at the same moment used to write the same new finding twice. They now take a lock and write it once.

## Changed

- Running `lattice-scan` with nothing used to fail with exit status 2 and a message; it now does the daily check and exits 0 unless Lattice or the list cannot be reached.
- A run that has to wait for the keyless limit takes longer than before in exchange for not failing. With a key there is no waiting.

## Known limits

- `recent` lists what was recently added, and matches by product name. An empty or all-`unmatch` result is not the same as safe.
- The hourly (20) and daily (60) keyless allowances still end a run; a key lifts them.
- The host check is tested on Debian-family hosts.
