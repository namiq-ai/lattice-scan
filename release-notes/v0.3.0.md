# lattice-scan 0.3.0

**A way in when you have no CVE id.** Until now the tool and its Claude skill needed a CVE id to start, and an agent asked "is this server exposed?" had none. This release adds three commands and changes the skill to match. It does not change what leaves the machine: package names, versions and the inventory are still never sent.

## Highlights

- **`lattice-scan recent`.** Reads namiq.io's daily or weekly list of recent exploited and critical CVEs (`--daily` for the last day or two, `--weekly` for seven days; weekly is the default). It rules out locally every exploited entry this host cannot have, reads only the likely matches from Lattice by exact id, and lists the rest as `unmatch`. A critical entry that may match is `WATCH` (not known to be exploited, so Lattice is not asked). With no match it sends nothing to Lattice and says that this is not the same as safe.
- **`lattice-scan enrich`.** Give it text that holds CVE ids (a `npm audit` or `pip-audit` report, an advisory, a ticket) on standard input, with `--file` or with `--cve`. Each id is read once and the table says: exploited by CISA's list, since when, patch due, CVSS, ransomware. It does not compare with the host and writes nothing.
- **`lattice-scan get-key`.** Requests a Lattice key for a real person who gave their name, position, company and a mailbox they read, and agreed to the beta terms. Nothing is sent without `--accept-terms`. The key goes to a private file (mode 0600), is never printed, and later runs use it by themselves. The person gets a confirmation email; "not me" withdraws the key.
- **Retries.** A Lattice request that times out (for example `The handshake operation timed out`) or gets 502, 503 or 504 is tried up to three times before the run stops.
- **The Claude skill starts with a "which command" table.** No id: `recent`. Ids in pasted text: `enrich`. A named id: `--cve`. A project folder: `project`. It also says how to ask a person for a key, and that it never asks for one alone.

## What leaves the machine

- `recent` downloads a public list from namiq.io. That request carries no CVE id and nothing about the host.
- Ids that may match are sent to Lattice one at a time, as before.
- `get-key` sends the name, position, company, email address and purpose you give it, to the key service, and only after `--accept-terms`.

## Changed

- The skill's old rule "do not request a key" is replaced by the procedure in `SKILL.md` section 5: ask the person, show the terms, get a clear yes, then run `get-key`.
- Exit status 3 now also means `enrich` stopped at the limit or read fewer ids than it found.

## Known limits

- `recent` lists what was recently added or published. An empty or all-`unmatch` result does not mean the host is safe, and a CVE older than the lists is not in them: use `--cve` for a CVE you know of.
- The local comparison is by product name, as in the host check. It can miss a product installed under an unrelated name, and a match is a candidate for a person to read, not a finding.
- Without a key Lattice allows about 20 reads an hour and 60 a day. `recent` stays well under that; a long `enrich` list does not, and says which ids it did not read.
- `recent` needs namiq.io's list, schema `lattice-recent/2`; an older tool cannot read it and an older list cannot be read by this one (the message says to upgrade).
- The host check is tested on Debian-family hosts.
